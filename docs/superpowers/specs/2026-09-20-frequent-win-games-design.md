当前源码中，刮刮乐和召唤只允许固定整数倍率，服务端按整数倍率直接乘下注额；数据库的结果表也有整数倍率集合约束。因此 1.2 倍必须贯穿配置、结算、持久化、历史与展示，不能只改奖池权重。

老虎机使用五个独立的 32 停点卷轴、十条固定中奖线。其等概率结果空间为 32^5；仅调整奖表不能让净赢结果数精确等于该空间的 70%。本设计保留卷轴、十条线、连线判奖及逐线派彩，明确更换停点抽样规则。

## 3. 固定新奖池

以下倍率均指相对于本次下注的总返还，包含本金：

| 结果 | 总返还倍率 | 整数权重 / 100000 | 概率 |
| --- | ---: | ---: | ---: |
| 未中 | 0 | 20000 | 20% |
| 回本 | 1 | 10000 | 10% |
| 小赢 | 6/5，即 1.2 | 60000 | 60% |
| 中赢 | 2 | 9000 | 9% |
| 大赢 | 5 | 1000 | 1% |

- 净赢率：60% + 9% + 1% = 70%。
- 理论返还率：0×20% + 1×10% + 1.2×60% + 2×9% + 5×1% = 105%。
- 净期望：+5%；净输率：20%；回本率：10%；最高奖概率：1%。
- **新规则的最高奖为总下注的 5 倍；原有 10 倍、20 倍、25 倍、100 倍及老虎机更高大奖不再出现在新局中。旧局仍保留原奖表。** 这是将收益从罕见大奖移向频繁小赢的明确取舍。
- 不依据账户、输赢历史或余额调整概率；各次抽样独立，不追赶实测返还率。

### 单次与十连口径

刮刮乐以一张卡为一次，老虎机以一次完整旋转为一次。召唤的 70% 是每一抽，不是十连整轮。

十连继续使用十次独立抽样，整轮成本为单抽下注的十倍，整轮输赢由总派彩与总成本比较。对本奖池进行整数卷积得到：

- 十连整轮净赢率：`17952251494627/31250000000000`，约 57.447204783%。
- 十连整轮回本率：`1119694951973/31250000000000`，约 3.583023846%。
- 十连整轮净输率：`60890267767/156250000000`，约 38.969771371%。
- 十连整轮返还率仍为 105%。后台同时列出单抽与十连口径。

## 4. 实现设计

### 4.1 刮刮乐与召唤

- 新建独立规则、奖池和配置版本，不修改已冻结版本的构造、配置哈希或抽样域行为。
- 新倍率使用整数分子、整数分母；分母为 5 时，0、1、1.2、2、5 对应分子 0、5、6、10、25。旧版本保持原整数表达，分母为 1。
- `Reward`、单抽结果、数据库结果快照和 API 必须携带新倍率的分母；旧数据缺省为 1。金额仍用整数原子单位，不使用浮点结算，不将 1.2 四舍五入成整数。
- 新配置显式声明倍率分母；旧 canonical JSON 不增加缺省字段，确保旧哈希不变。
- 金额乘除采用先约分再乘的有界计算；沿用下注步长并验证整除和溢出条件。当前步长 500000 原子单位可被 5 整除。
- 新奖池只启用表中五档；现有符号与等级外观可以复用，但倍率文字和最高档排序必须来自该局配置，不能继续依赖旧符号名称或字符串顺序推断奖金。
- 刮卡结果仍在购买时确定；余额、派彩及相关汇总在揭晓前保持现有防泄漏行为。

### 4.2 老虎机

选择“加权有效停点组合”方案，不做结算后金额覆盖，不把未中奖画面标成中奖：

1. 复用现有卷轴、十条线和 `FairConfig` 奖表，从真实停点组合中固定选取总返还分别为 0、1、1.2、2、5 倍的组合。
2. 每个倍率档收录 32 个不同停点组合，总计 160 个；组合列表与权重纳入新配置哈希。
3. 使用公平随机流先按五档权重选档，再在该档 32 个组合中等概率选择；使用独立且版本化的抽样域。
4. 最终画面与每条线金额仍由原有连线判奖函数重新计算。每条线派彩之和必须等于本局派彩，不接受展示结果与到账金额分离。
5. 新规则命名并说明为加权停点组合；玩家规则保留这一机制说明，但不展示具体数值概率。后台明确标注“非五卷轴独立均匀抽样”。

本轮只读可行性核对已找到每档 32 个有效不同组合；检查了 184153 个候选组合。此结果证明候选存在，不代替后续 Go 引擎对全部 160 个冻结组合逐线复算。

取舍：这是一个有限的固定组合池，而不是保留原来所有 33554432 种组合及其独立均匀分布；旋转画面的组合多样性会相应降低。旧版老虎机继续沿原路径复算。

### 4.3 骰子与 21 点

- 骰子现有 v2：净赢 `105/216`、净输 `105/216`、回本 `6/216`、RTP `1/1`。仅增加后台展示，不改结算。
- 21 点继续使用现有参考策略验证资料：参考策略、样本数、RTP 点估计、置信区间、初始下注和追加下注的统计口径分别注明。
- 现有 21 点验证资料未包含净赢率时，显示“未记录该统计”，不填 70%，不把实测值冒充理论值，也不额外运行千万局模拟。
- `recoverBlackjack` 及其已修复的 pending 恢复行为保持原样。

## 5. 版本、持久化与历史兼容

- 新增前向数据库迁移，为分数倍率增加分母及对应约束；旧数据分母为 1，旧值和旧记录不重写。
- 新配置记录、新算法/规则标识与验证资料一一绑定；新局只使用已验证的新版本。
- 保留所有旧版本加载与复算路径；历史记录、已购买刮卡、旧承诺和进行中的 21 点继续使用创建时快照。
- 沿用现有配置激活与过期承诺处理流程；过期承诺刷新后再受理新下注，不在扣款后偷偷换配置。
- 注意当前部分统计资料按游戏名全局选择：新实现必须按配置/规则版本选择对应资料，避免旧局被显示为 70%/105%。
- 金额、每抽派彩、整轮派彩、钱包流水和结果分类在同一权威结算路径保持一致，继续复用现有幂等和事务。
- 新概率方案为固定版本；不新增后台调概率入口。既有旧版草稿管理保留，新格式不进入旧整数倍率编辑器。
