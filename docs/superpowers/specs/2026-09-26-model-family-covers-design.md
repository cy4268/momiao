# 模型家族封面管理设计

日期：2026-09-26。状态：书面方案待评审，尚未实施产品改动。

代码基线：`3542600ac048263bae18877baff77a85b7212a76`。

## 目标与现状

管理员在模型运营页上传、预览并确认家族封面后，公共模型目录、家族页和具体模型详情使用同一张新图。一个家族只显示一个目录卡片，具体模型与渠道仍在详情内选择。

已确认的约束：保留现有九套模型形象；使用 R2 和自定义 CDN 域名；浏览流量不经过业务服务器；保留权限、确认、版本、审计和模型发布状态；阶段源码上传，网站统一部署。本项不扩大为通用素材管理器，不接入 Cloudflare Images，不改认证、钱包、游戏、价格或模型调用逻辑。

源码核对发现两个实际缺口：

- `web/src/OpsCatalog.tsx` 只有选择已有 `asset_id` 的下拉框，没有上传入口。图片词表由 `internal/platform/catalog-personas.json` 编译进服务。
- `web/src/Catalog.tsx` 的 `CatalogPersona` 优先选择固定家族图，再考虑单模型 `asset_id`。因此，为单个模型选择图片并不能可靠改变已配置家族的卡片。

既有模型发布生命周期的 PostgreSQL 定向测试已通过，但这不能证明新增图片上传、公共图片回读或其余所有后台业务已经验收。当前私有样式预览也不作为真实后台写入证明。

## 选定方案

本稿采用推荐路径：**只有管理员上传新文件时，经业务服务器校验一次再写 R2；所有图片展示均直接访问 CDN。** 这一上传路径假设需要在本稿评审时确认。

```text
管理员选择文件 → 同源上传接口 → 格式/尺寸校验 → R2 版本对象
                         ↓
                   登记待选图片
                         ↓
                预览 → 确认家族绑定
                         ↓
                    PostgreSQL

用户 → 模型目录接口取得已生效的家族封面路径
     → VITE_ASSET_BASE_URL + 相对路径 → Cloudflare Cache → R2
```

方案比较：

| 方案 | 结果 |
| --- | --- |
| 管理员上传经过服务端一次 | 推荐；复用同源认证，服务端完整校验文件，不承接日常看图流量。 |
| 浏览器签名直传 R2 | 可减少上传的服务器流量，但增加签名、CORS、暂存与最终对象校验；签名 URL 在过期前可复用，不能把可覆盖的对象直接作为 immutable 封面。首版不采用。 |
| 管理员手填图片链接 | 仍需去别处上传，并易出现失效或外部链接；不能解决缺少上传入口的问题。 |

R2 的 S3 签名地址和自定义 CDN 域名用途不同；直传方案还需要桶 CORS。服务端使用官方 AWS SDK for Go v2 对接 R2，而不手写签名协议。[Cloudflare 签名 URL 文档](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)、[Go SDK 示例](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-go/)

## 后台与前台交互

- 在 `/ops/models` 放置明确的“家族封面”入口。选择家族后显示当前封面，提供“上传新图”和“恢复默认封面”。沿用已确认的后台面板和确认弹窗，无新一轮美术重绘。
- 模型编辑页显示其所属家族的当前封面及管理入口；移除容易误解的逐模型图片选择操作。旧 `metadata.asset_id` 字段和数据保留，不用批量覆盖每个模型来同步图片。
- 上传面板使用原生文件选择器，显示格式、大小、预览、替代文字和素材来源说明。来源状态沿用现有允许的三类：平台原创、生成原创、已获许可。
- 上传成功只是准备候选图片，不立即改前台。弹窗展示家族、旧图、新图和“影响该家族全部模型”的说明，填写原因后确认生效。
- 上传前明确说明：目标桶用于公开素材，文件上传后具有公共访问地址；确认控制的是目录绑定，而非文件保密状态。
- 预览必须实际加载 CDN 地址；图片失败时保留当前封面并呈现可重试的上传/预览状态，不显示虚假的成功结果。
- 列表卡片、家族详情、具体模型详情统一使用服务端返回的家族封面。筛选、排序、切换渠道不改变同一家族的图片。
- 新请求读取新绑定；已经打开的公共页面在刷新或重新进入后更新。本期不增加轮询或实时推送，也不声称后台保存后所有已打开页面瞬间改变。
- 公共图加载失败时回到该家族原批准图；两者均失败时保留文字、链接和布局，不以 Emoji 或临时几何图冒充人物图。没有内置人物的 `other` 家族，在未配置封面时保持文字可用。
- 后台遵循现有桌面固定外框、面板内部滚动和手机自然滚动；上传、预览和确认可用键盘完成。

## 数据与接口

### 持久化

新增一份前向迁移，使用实施时的下一个空闲编号（当前最后编号为 0039），不改旧迁移。

1. `catalog.family_cover_assets`：不可变上传记录。保存图片 ID、家族、内容 SHA-256、对象键、类型、字节数、宽高、替代文字、来源状态/说明、创建人及时间。相同家族与内容哈希唯一；旧图片记录保留。
2. `catalog.family_covers`：每个已支持家族一行，保存可空的图片 ID、版本和更新时间。空图片 ID 表示使用现有内置家族图。绑定必须引用同一家族的上传记录。迁移初始化版本为 1，后续恢复默认也递增版本，不删除行或把版本归零。

同一家族重复上传相同内容时复用已登记图片，返回其原有替代文字和来源信息，并提示“图片已登记”；这不是修改旧图片元数据的入口。不同家族可独立登记相同内容。

沿用 `ops.model_previews` 存预览和 `ops.admin_operations` 存回执、前后状态与审计，不另建一套预览/审计系统。家族封面操作使用独立 action 和 family 标识，`model_id` 留空；不绑定任意代表模型，也不借用来源同步版本。

生产最小授权脚本同步增加：图片记录 SELECT/INSERT、家族绑定 SELECT/指定列 UPDATE。运行角色不获得 DDL、删除历史或改写审计权限。真实运行角色验证需与迁移一起覆盖，不能只用数据库 owner 验证。

### 接口契约

在现有模型运营路由内增加专用操作，不改变原模型 SAVE/PUBLISH/HIDE/RETIRE/SYNC 请求含义：

| 接口 | 语义 |
| --- | --- |
| `GET /platform/v1/ops/models/family-covers` | 返回已知家族、当前图、默认图、版本及上传配置是否就绪；不返回存储密钥。 |
| `POST /platform/v1/ops/models/family-covers/upload` | 同源 multipart，单文件及家族、替代文字、来源说明、原因、权限 epoch、操作编号；返回登记成功的候选图，不改变绑定。 |
| `POST /platform/v1/ops/models/family-covers/prepare` | JSON，SET 或 RESET、family、候选图片 ID、expected_version、epoch、reason、operation_id；返回旧新图和有效期内的 preview_id。 |
| `POST /platform/v1/ops/models/family-covers/execute` | 同一命令、preview_id 和明确 confirmed；重新校验后事务提交，返回版本与回执。 |

公共模型对象增加可选 `family_cover` 投影，内含家族、版本、当前可用图片和内置备用图的公开描述。上传者、存储账号、内部错误和未绑定图片不进入公共接口。所有公共列表与详情在其现有数据库读事务内取得同一套封面解析结果，不按每个模型单独发查询。

`CatalogPersona` 在新响应下只依据这一投影，取消“固定家族图总是覆盖后台选择”的优先级。旧服务没有此字段时兼容现有内置词表；新服务必须明确返回默认状态，不能把空值误解成继续读取失效的单模型设置。

`CatalogChoices()` 与旧 `metadata.asset_id` 校验继续服务于既有内置资产；新上传记录通过独立家族绑定生效，不把整个上传库塞入模型编辑词表。

## 文件与 CDN

- 接收静态 PNG、JPEG、WebP；单文件最多 8 MiB，任一边不超过 8192 像素，总像素不超过 16,777,216。先限流式读取字节数和解码尺寸，再完整解码验证；拒绝损坏、动画和其它格式，不仅信任扩展名或请求 MIME。
- 使用标准库 PNG/JPEG 解码及 Go 官方扩展库的 WebP 解码；不引入图片编辑框架。首版不裁剪、压缩或转码原图。
- 不接受 URL 抓取，不采用原始文件名作为对象键。服务端生成 `assets/models/uploads/<family>/<sha256>.<ext>`，保存经过验证的原始字节，扩展名由实际格式确定。
- 相同哈希仅代表相同内容；上传接口不接受任意键或覆盖现有批准图。返回的相对图片路径通过已有 `assetUrl` 与 `VITE_ASSET_BASE_URL` 拼接。
- R2 对象设置准确 Content-Type 和 `Cache-Control: public, max-age=31536000, immutable`。替换图片创建新哈希路径，不覆盖旧路径，不清全站缓存。
- 现有自定义域名和缓存规则需核对是否覆盖新 `assets/models/uploads/` 路径及 JPEG；仅对象缓存头存在不等于边缘命中已验收。验收要读取实际域名的状态、类型、缓存响应和内容哈希。自定义域名的缓存行为以 [Cloudflare 公共桶文档](https://developers.cloudflare.com/r2/buckets/public-buckets/) 为准。
- 后端新增桶账号、桶名和凭据文件路径配置；凭据从部署侧只读密钥文件加载，权限限制到素材桶。前端仅获得公开图片地址，仓库和日志不包含凭据内容。
- 配置全缺时禁用“上传新图”并清晰说明，已有模型读取、当前封面和恢复默认不受影响；部分配置或错误配置在启动时报告错误，不静默换成服务器本地存图。

## 权限、确认和失败处理

- 查询遵循现有模型运营访问权限；上传需要 `models.write`，SET/RESET 公开家族绑定需要 `models.publish`。客户端按钮显隐不能代替服务端检查。
- 复用现有会话、精确 Origin 校验和授权 epoch。JSON 接口仍严格解码；multipart 上传在具体分支单独解析，不放宽其它运营写接口。
- 上传使用独立的有限超时和单文件大小上限，不沿用当前模型 handler 的 8 秒上下文导致正常 R2 上传被截断；也不全局加长其它接口超时。
- 上传登记时再次确认授权。对象写入成功后，图片记录与上传审计同一数据库事务提交；中途失败不改变家族绑定。跨 R2 与 PostgreSQL 不伪装成一个原子事务：R2 已写入但登记失败时留下未绑定对象，按相同内容重试收敛，不自动清理其它对象。
- 相同操作编号、操作者和同一命令重试返回原回执；同编号不同内容返回冲突。上传编号也绑定内容哈希及元数据，不能替换文件后复用旧成功回执。
- 确认命令绑定候选图、家族、预览哈希、版本、操作者和 epoch；提交前重新校验权限、预览有效期、图片存在及版本。两名管理员并发编辑时，旧版本操作失败并重读，不覆盖较新修改。
- 候选图绑定、版本递增与审计同一事务提交。发生失败保留旧封面；确认成功但后续读取失败时保留已确认回执，不误导管理员重复新建操作。
- 上传文件、R2 凭据、内部 S3 响应和栈不进入公共错误或审计正文。审计保留对象哈希、家族、前后绑定及操作原因。

## 最小验收

本设计文档只做内容、差异、隐私和独立副本回退核验，零应用测试。以下是实施阶段的验收要求，不代表已经执行：

- 优先扩展现有 `TestCatalogOpsPublicationLifecycleAndIdentityHistory`、`TestCatalogOpsRunsUnderRuntimeGrants`、`TestCatalogHTTPProtectedWrites`，覆盖绑定/恢复、旧版本、权限撤销、重复操作和公共投影；前端复用现有 OpsCatalog 与 Catalog 用例，保留原模型编辑流程断言。
- 最多新增一条上传链路回归，覆盖真实解析、坏文件/超限拒绝、R2 写入失败与成功登记。复用现有测试替身与标准库工具，不增加测试框架、产品 fixture 或逐函数测试。
- 只运行上述被扩展/新增的定向用例和前端构建，不运行本地全量套件；若发现共享授权逻辑必须修改，先给出具体风险和扩大的命令。
- 用既有本地真实 handler/数据库预览：后台上传并确认 → 匿名目录重读 → 同家族不同模型详情 → 刷新页面。必须验证接口里的图片 ID/版本和浏览器实际 CDN 图片一致，而不只修改私有预览数据。
- 单独核对 1440×900 桌面和 390×844 手机的上传、确认、失败反馈和前台卡片；实际 R2/CDN 的 HTTP 200、Content-Type、哈希及缓存响应另行留证。测试上传使用专用新版本键，不覆盖现有图。
- 如果只完成本地存储替身验证，记录为“代码验证通过，真实 R2 联调未验收”；不将其写成图片功能全部完成。

## 发布与回退

源码阶段完成后脱敏提交并上传当前功能分支；不合并主分支、不部署网站。本期先使代码与本地真实业务流程可验收，部署时才启用正式凭据和新迁移。

正式发布顺序是备份、前向迁移/最小授权、服务端、前端；接口字段只增不删。旧前端可以继续读取旧词表，故不保证旧版本页面展示新封面；新版上线后以统一投影为准。

业务回退优先通过确认流程恢复该家族默认图，保留审计和旧对象。源码回退在独立副本验证，不删除 R2 对象、不逆向删表、不回写历史数据。回退老应用将使用原内置图，数据库新表和操作历史保留。
