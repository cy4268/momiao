# 0006 — Master 资料的独立交付切片

以本人资料页接通设计内的 Master 展示身份，不把原生用户名或 display_name 复制成已完成的 Master。

## 保留的业务语义

- 1–24 Unicode grapheme、NFKC + Unicode case fold 判重、数据库并发唯一性；拒绝控制/不可见字符、Emoji 和非允许符号，服务端维护保留名基线。
- Master 初始化必须由本人明确提交。修改昵称不改登录标识、原生账户、钱包或历史归属。
- 首次初始化不消耗改名冷却；后续真实改名使用数据库时间并进入7天冷却，追加不可变名称历史。
- 使用稳定 `newapi_user_id` 归属；版本号字符串 + 行锁避免旧页面覆盖新资料。相同初始化重试不重复创建记录或历史。
- V1 不上传自定义头像，不增加 Bio 或他人公开 Profile。

## 本轮收缩与代价

1. 本人 `/master-profile` 独立接入，暂不强制现有门户全局 onboarding。GET 无副作用：未保存时返回 INCOMPLETE/version0 投影，首次提交才原子建立完整记录。代价是全站首次认证自动生成 provisional profile 和游戏入口强制门禁仍待后续实现；现有门户不因未填资料或资料库故障而阻断。
2. 唯一可选头像为既有 Crest 的静态系统默认头像 `system-default`。外部账号同步、快照下载和最终角色美术留给相应集成；页面不显示假的同步/上传控件，也不将模型 Persona 当成 Master 头像。
3. 本轮执行字符规则、有限保留名/明显等价形式校验和数据库唯一性。完整敏感词运营词库、审计化强制改名/名称释放及更广泛冒充检测尚未实现；有限名称列表不等于全面内容审核。公开游戏/排行前需继续落实相关门禁。
4. 复用现有平台库与固定原生认证 transport，不增加密码权威、第二数据库或新的全局状态框架。运行角色只增加资料所需列权限，经济写权限仍不授予。

接口见 [Master 契约](../../contracts/master-profile-api.md)。本切片不发注册赠金、不改奖励资格，也不把资料保存成功等同资金入账。
