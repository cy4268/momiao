# 0002 — 先交付可用门户，迁移不阻塞改造

状态：采用。

当前优先级从迁移准备转为真实使用流程：登录、指挥台、API Key 管理与个人调用日志。沿用 Bright Moonlit 视觉方向，连接原生 NewAPI，而不是再交付一套合成数据原型。

- React/TypeScript 负责界面与小型 HTTP Adapter；Go 负责构建产物与固定 Unix 上游转发。保留同源原生 `/api/` 路径，让 HttpOnly 刷新 Cookie 的范围不变。
- 会话身份、权限、API Key 与原生额度由后端裁定；不造第二套未经验证的账户/资金系统。访问令牌只在页面内存中，刷新凭据由原生 Cookie 持有。
- 原生额度明确以原生单位显示，不混称为未来平台的 API Credit、Reserve 或游戏资产。
- 旧数据迁移从当前关键路径移出；不因此删除旧数据或重置旧站。正式迁移保留为独立可选增量。
- 当前入口是本仓库实现的门户，不再是原生前端外观；但未实现的账本、奖励、游戏与模型渠道不据此宣称完成。

本记录覆盖历史实施顺序中将全量迁移/全部 SV 作为此门户工作的前置条件。涉及已接入接口的证据仍来自确切原生源码与运行行为。旧的最小进程结构保留，但按真实需求增加 `web/`，不建立未使用的微服务。
