# 0005 — 钱包查询先接入，资产变更保持关闭

## 范围

新增 `/wallet` 和自有 `/platform/v1/wallet` API：每次请求核验原生身份，显式创建两个零余额钱包，读取余额和流水。Master 昵称/头像、奖励、充值、兑换与游戏不在这一批；原生 display_name 不是平台 Master 资料的替代品。

GET 不建用户或钱包。POST 初始化仅接受同源 JSON 空对象，对核验出的用户幂等确保零行；不把初始化当作注册赠金或迁移赠金。角色和 ID 不由浏览器决定，Cookie 不作为钱包 API 的认证凭据。

## 数据隔离

平台使用独立 PostgreSQL 实例/数据库，不复用原生实例的信任认证入口。参考部署只监听受保护 Unix Socket、所有本地连接使用 SCRAM，数据库没有网络接口。Owner 不登录；运行角色仅可查询，并向身份锚点/钱包的指定列 INSERT，余额 UPDATE、非零余额 INSERT、流水写入、DDL 和 owner 切换均未授权。

保留 A1 内部账变库供后续业务使用，但本版 HTTP 接口和运行角色都不开放它。追加历史保护与最小权限互补，不把数据库超级用户视作受这些限制保护的调用者。

## 可用性

钱包配置为可选且成对设置。运行时只建立惰性连接池，不在启动时 Ping 或迁移；数据库不可用时钱包返回 503，原有门户、原生 API 代理不因此停机。非法配置文件/连接配置仍属于启动错误。显式迁移命令单独执行，拥有连接验证与管理权限。

原生身份服务的 401、403 和连接/格式错误分别处理。403 不转换成全站登出；上游故障不伪装成登录失效。

## 视觉与资产语义

配色、排版、空状态、错误与手机布局随本功能一起完成。只展示本地 Reserve 与可用筹码，不计算缺少其他权威数据的总资产。原生 quota 仍在指挥台单独展示。立绘、拟人图与复杂动效继续按稳定模块补齐。
