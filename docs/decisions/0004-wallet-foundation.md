# 0004 — 从真实账本基础开始平台经济

## 决定

在可用 API 门户之后，先实现 `internal/platform` 中最小 PostgreSQL 存储基础；本批不新增资产写入 HTTP 接口，也不改变已运行门户的启动方式。

- 复用原生身份：`identity.account_refs` 仅保存外部 ID 锚点，不保存密码、用户名权威或原生账户状态。固定来源的 `model.User.Id` 为 Go `int`，已运行的 PostgreSQL `users.id` 实测为 `bigint`；新的来源版本仍需重新核验。
- 本地余额只有 `RESERVE_API_CREDIT` 和 `AVAILABLE_CHIPS`。新身份与两个零值钱包在同一事务幂等确保；Active quota 留在原生系统。
- 金额使用 `int64/BIGINT`。沿用 500000 atomic units/credit 的明确业务单位；输入最多六位小数且必须精确表达。JSON 中金额为字符串。
- 内部单钱包账变把幂等记录、业务交易、余额与追加账本放在同一 PostgreSQL 事务。重复请求返回原始结果，不重新扣发；冲突与结果未知不自动重试。
- 只增加本批实际使用的表及显式迁移入口。迁移带校验和，门户启动不自动迁移；不预建所有游戏、奖励及运营表。

## 本批的边界

这是账户与钱包一期的 A1 存储基础，不是经济系统上线。它尚未包含 Master 昵称/头像流程、面向用户的钱包接口与页面、受限数据库运行角色接入、多资产事务、quota Saga、奖励、充值或游戏。

仓库中的数据库测试只能使用明确配置、名称以 `momiao_test_` 开头的独立测试库。测试结果不证明生产容量、最小权限配置或灾难恢复；正式接入前分别完成这些验收。

## 美术节奏

配色、排版、组件状态、可访问性和移动端布局随功能一起交付，保留 Bright Moonlit。角色立绘、模型拟人素材和复杂动效在对应页面布局稳定后按模块补齐，不等全站开发结束，也不让大批生图挡住账本、身份和业务实现。

## 后续

A2 接入服务端核验的原生登录身份、受限数据库连接与真实钱包/流水查询页面；再实现业务入口和完整资产事务。旧数据迁移不在当前关键路径，旧服务保持原状。
