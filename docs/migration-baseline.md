# 迁移基线：规则与证据状态

**状态：尚未实现迁移；没有生产 SQL、迁移器、平台数据库或 Cutover。** 此文档不含生产计数、地址、快照指纹、账号或执行命令。

## 保留与重置规则

- 保留既有账号、绑定、密码及原生哈希、Key/Secret 关系、渠道、模型与倍率/计费配置、历史 API 日志、系统配置，以及迁移前 quota 审计快照。正式字段映射由准确版本与真实 schema 核验决定，不从设计稿推断生产表结构。
- 只有正式 Cutover 才执行需求定义的四类旧资产重置；对每个已确认迁移用户向 Reserve 发放 **1,000 API Credit**。本基础没有重置或发放代码。
- 迁移赠金幂等业务键：`initial_grant:migration:{migration_batch_id}:{user_id}`。不通过注册回调发迁移赠金，不对同一批次重复发放。
- 新账变开放后，单独恢复旧 quota 会形成混合经济状态；回滚必须按事先演练的整套数据与写入边界执行。
- 密码、API Key、上游凭据与密钥材料保留在受限恢复链路；公开仓库既不存储也不生成它们。

## 当前证据的真实含义

已有来源阅读与隔离合成账号的部分原生 HTTP 行为观察，但整体验证仍为 **PARTIAL**。没有平台 Adapter，也没有证明完整的密码 SET/RESET、Session rotation、OAuth 绑定/管理员重绑、故障并发或资产/API Key/历史归属合同。

已观察到的关键差异需要在相应功能继续验证：HTTP `200` 与业务 `success` 不等价；资料更新成功不证明密码更改；Session、dashboard token 与 PAT 的撤销语义应分别判断；多字节密码同时受字符和 UTF-8 字节约束；对空绑定的 clear 成功不证明已填充绑定清除或重绑。

已有只读计数不是跨表一致快照，备份校验和吻合也不证明可恢复。镜像标签与源码/二进制指纹不等于签名或可复现构建证明。原始操作证据保留在独立受限位置，不随本公开仓库发布。
