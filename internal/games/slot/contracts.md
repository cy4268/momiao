# Slot v1 pure engine integration

Authority: the project implementation specification, IS-06 §§248–249, 265, 273–276; Technical Design §§327–340; baseline §10 Direct Play wager policy. This module is not a playable service, wallet integration or production availability approval.

## Entry points

```go
FrozenConfig() Config
Resolve(wagerUnits int64, stops [5]int) (Result, error)
Spin(wagerUnits int64, sample func(domain string, n uint32) (uint32, error)) (Result, error)
```

- Five stops are zero-based `[0,31]`; grid is reel-major `[5][3]`, rows top/middle/bottom.
- `Spin` requests exactly `slot:reel:1` … `slot:reel:5`, each with `n=32`. Bind each domain to the shared fairness stream; adapt its `UniformInt(reader, uint64(n))` return to `uint32`. No additional seed generator, hash stream or random library exists here.
- Amount inputs/outputs are `int64` atomic units, 500,000 per Chip. Initial wager is any whole Chip >=10, including 11. Ten lines always enabled. `Lines` contains all ten rows, including zero returns; line numbers are 1–10.
- `Result` and line amount JSON fields use decimal strings. Multipliers and small indexes are JSON integers.
- Returned `TotalPayoutUnits` includes any returned principal; apply that credit once, not payout plus initial stake. `Class` is net-based; `Detail` distinguishes no win and partial return.
- Validation occurs before sampling. Initial integer bound reserves the frozen maximum 5164 line multipliers; line multiplication and total addition also check overflow. No new product-level fixed maximum is introduced.
- Errors leave no external effect. A failing sampler may already have consumed stream bytes: discard that attempted stream and rebuild it from the same bound round input for a retry.

## Versions/config boundary

```text
implementation_key = direct.slot.v1
ruleset_version = slot-rules-v1
algorithm_version = slot-map-v1
config_schema_version = slot-config-v1
reel_strip_version = slot-strips-v1
payline_version = slot-paylines-v1
paytable_version = slot-paytable-v1
```

`FrozenConfig()` returns independent value arrays containing the verbatim frozen strips, symbols, lines and paytable. It is a rules payload source, not permission to edit an already active/historical config. The shared layer must reject mismatched locked rules/config versions; this engine intentionally has no arbitrary custom-paytable argument.

Shared config code owns `CHALDEA_GAME_CONFIG_CANONICAL_JSON_V1`: UTF-8 key byte order, preserved arrays, integers/no float, duplicate-key rejection, canonical escaping. Hash is SHA-256 of `ASCII("CHALDEA-GAME-CONFIG-V1\x00") + LP16(game_slug) + LP16(config_schema_version) + LP16(algorithm_version) + canonical_json(config_payload)`. Round envelope/config hash, commitments, durable nonce, transactions, typed result storage and activation gates stay outside this module; no second config hash implementation is supplied.

## Verification scope

Local tests cover all 160 frozen strip entries and per-reel frequencies, wild own/substitute maximum paid once, five-chain non-stacking, left-to-right minimum length, stop/grid/replay, exact 11-Chip arithmetic, out-of-range inputs, stream failures and integer overflow. The 32^5 production exhaustive validation and its config-bound VERIFIED artifact are **not generated by this change**. Frozen RTP and maximum figures are source requirements, not freshly measured validation results.
